## First batch: Button and Text Input

Only these two components change. Button retains hierarchy, size, icon, native type and preview APIs; Text Input retains native value/validation and loading APIs. Implement inside-stroke geometry, Ghost underline/focus anatomy and mobile required-marker metrics; compare disabled Text Input bindings with main definitions. Add explicit Light/Dark, 320px content-width and long-content review cases. Preserve native keyboard focus/activation, disabled precedence and destructive focus. Do not add Button loading or a public pressed variant: current Figma explicitly leaves pressed undefined and scope asks for later loading/API decisions. Do not add every mathematically possible variant combination; Ghost icon-only and Secondary/Ghost Danger remain unsupported design combinations even though the legacy API accepts them.

## Acceptance and unresolved decisions

1. Compare Button 48/40/32px and Text Input desktop/mobile 48/40px field geometry against exact source nodes, including Inter metrics, padding, 4px radius, strokes, focus effects and semantic bindings. Text Input source width is 460px; at narrower widths preserve readability and native semantics without treating a mobile typography variant as a fixed phone viewport.
2. Check keyboard activation and form submission; disabled controls cannot activate; label/description/error association; focus visibility including destructive focus; value changes and applicable loading replacement.
3. Render source-width and 320px content examples in Light/Dark. A build, jsdom test or token check does not prove rendered parity, font availability, icon equality or accessibility compliance.
4.
