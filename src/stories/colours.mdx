# Colours

Colour creates hierarchy, communicates status, and connects every DDS experience to the brand.
The system separates **primitive palettes** from **semantic tokens** so components express intent
without depending on a particular shade.

<div className="dds-colours__callout">
  <strong>Use semantic tokens in product code.</strong>
  <span>
    Primitive tokens are the raw palette. Semantic tokens describe purpose and can evolve without
    requiring component-level changes.
  </span>
</div>

## Primitive palette

Primitives are the fixed colour values from which semantic decisions are made. Avoid referencing
them directly inside components unless a matching semantic token does not yet exist.

{palettes.map((palette) => (
<section className="dds-colours__palette" key={palette.name}>
<div className="dds-colours__section-heading">
<h3 id={`palette-${palette.name.toLowerCase()}`}>{palette.name}</h3>
<p>{palette.description}</p>
</div>
<div className="dds-colours__primitive-grid">
{palette.colours.map(([token, value]) => (
<PrimitiveSwatch key={token} token={token} value={value} />
))}
</div>
</section>
))}

## Semantic colours

Semantic tokens connect colour to a repeatable role. Select the token whose name matches the
intended meaning—not the one whose current value merely looks right.

{semanticGroups.map((group) => (
<section className="dds-colours__semantic-group" key={group.name}>
<div className="dds-colours__section-heading">
<h3 id={`semantic-${group.name.toLowerCase()}`}>{group.name}</h3>
<p>{group.description}</p>
</div>
<div className="dds-colours__token-list">
{group.tokens.map(([token, alias, usage]) => (
<SemanticToken key={token} token={token} alias={alias} usage={usage} />
))}
</div>
</section>
))}

## Accessibility guidance

- Do not use colour as the only way to communicate meaning. Pair status colours with text, an icon,
  or another visible indicator.
- Validate text and interactive controls against their actual background. Aim for at least **4.5:1**
  for regular text and **3:1** for large text and essential graphical elements.
- Preserve visible focus indicators and test feedback states in context, including disabled and
  high-contrast environments.
- Use muted feedback backgrounds with their corresponding strong text, icon, or border token.

## Naming model

<div className="dds-colours__naming">
  <code>--text-colour-danger</code>
  <span aria-hidden="true">→</span>
  <span>
    <strong>category</strong> · property · role
  </span>
</div>

Token names use British English (`colour`) and describe the UI role. Component-specific tokens,
such as `--btn-colour-primary-hover`, add the component, variant, and state when a global semantic
name would be ambiguous.
